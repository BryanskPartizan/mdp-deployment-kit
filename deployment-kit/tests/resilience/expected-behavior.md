# Ожидаемое поведение при тестировании потери узла

- drain worker-узла должен запускать переразмещение stateless-нагрузок;
- ingress должен оставаться доступным, пока на исправном worker работает хотя бы один pod ingress-controller;
- Prometheus и Grafana могут временно потерять часть метрик, но control plane кластера должен оставаться доступным;
- stateful-нагрузки на локальном хранилище могут потребовать ручного переноса либо восстановления из резервной копии при окончательной потере узла.
